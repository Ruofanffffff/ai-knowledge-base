# Schema 驱动知识图谱系统 - 技术白皮书

## 摘要

本白皮书介绍了一种创新的 Schema 驱动知识图谱构建方法,通过规则优先、LLM 兜底的混合策略,实现了 90% 的 Token 消耗节省,同时保持高质量的知识抽取和图谱构建。系统采用四层架构设计,支持多种文档格式,覆盖科研、政府、生活等多个领域,为个人和组织提供了一个高效、低成本的知识管理解决方案。

**关键词**: 知识图谱、Schema 驱动、Token 优化、混合策略、知识抽取

## 1. 引言

### 1.1 背景

随着信息爆炸时代的到来,个人和组织面临着海量文档和数据的管理挑战。传统的文档管理系统只能提供简单的存储和检索功能,无法深入理解文档内容,也无法发现文档之间的关联关系。知识图谱技术为解决这一问题提供了新的思路,但现有的知识图谱构建方法存在以下问题:

1. **高成本**: 完全依赖大语言模型 (LLM) 进行知识抽取,Token 消耗巨大
2. **低效率**: 处理速度慢,无法满足实时性要求
3. **质量不稳定**: LLM 输出不确定性高,知识质量难以保证
4. **缺乏可追溯性**: 无法追溯知识来源,难以验证和修正

### 1.2 研究目标

本研究旨在设计和实现一个 Schema 驱动的知识图谱系统,实现以下目标:

1. **降低成本**: 通过规则优先、LLM 兜底的混合策略,减少 90% 的 Token 消耗
2. **提高效率**: 本地处理 < 1 秒,总处理时间 < 5 秒/文档
3. **保证质量**: 平均实体置信度 > 0.7,关系置信度 > 0.6
4. **可追溯性**: 每个实体和关系都能追溯到源文档的具体位置

### 1.3 创新点

1. **Schema 驱动架构**: 使用 250 个预定义 Schema 模板,覆盖多个领域
2. **4 层字段映射策略**: 精确匹配 → 相似度 → 同义词 → LLM
3. **智能字段截断**: 动态选择相关字段,节省 40% Token
4. **分层关系构建**: 内建关系 (0 Token) + 共现关系 (0 Token) + 语义关系 (最小 Token)
5. **置信度驱动**: 自动过滤低质量数据,保证知识图谱可靠性

## 2. 系统架构

### 2.1 四层架构设计

系统采用四层架构设计,从底层到顶层依次为:

```
┌─────────────────────────────────────────────┐
│           应用层 (Application)               │
│  - 前端可视化                                │
│  - API 接口                                  │
│  - 用户交互                                  │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│         知识图谱层 (Knowledge Graph)         │
│  - 实体构建 (Entity Builder)                │
│  - 关系构建 (Relation Builder)              │
│  - 置信度管理 (Confidence Engine)           │
│  - 图遍历 (Graph Traversal)                 │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│       Schema和规则层 (Schema & Rules)        │
│  - Schema 管理 (250 个预定义)               │
│  - 字段清洗 (Field Normalizer)              │
│  - 同义词词典 (Synonym Dictionary)          │
│  - 智能截断 (Intelligent Truncating)        │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│          CKB层 (Common Knowledge Base)       │
│  - 文档解析 (Word, PDF, Excel)              │
│  - 字段抽取 (Field Extractor)               │
│  - 结构化存储                                │
└─────────────────────────────────────────────┘
```

**设计原则**:

1. **CKB 是唯一入口**: 所有实体和关系必须可追溯到 CKB (最小事实单元)
2. **Schema 驱动**: 实体由 Schema 完整度触发生成,而非直接从文本生成
3. **规则优先,LLM 兜底**: 最大化使用规则和统计方法,最小化 LLM 调用
4. **置信度驱动**: 自动过滤低质量数据,保证知识图谱可靠性

### 2.2 核心模块

#### 2.2.1 CKB Parser (CKB 解析器)

**功能**: 将各种格式的文档解析为 CKB (最小可引用事实单元)

**支持格式**:
- Word (.docx): 提取段落和标题层级
- PDF (.pdf): 提取文本和段落结构
- Excel (.xlsx): 检测表头,每行生成一个 CKB

**输出**: CKB 对象,包含:
- `ckb_id`: 唯一标识符
- `doc_id`: 源文档 ID
- `source_type`: 来源类型 (word/pdf/excel)
- `content`: 文本内容
- `quality`: 源置信度 (0-1)

#### 2.2.2 Field Extractor (字段抽取器)

**功能**: 从 CKB 中提取结构化字段

**抽取策略**:
1. **规则抽取** (优先级最高): 使用正则表达式提取时间、数值、单位
2. **NER 抽取** (中等优先级): 使用命名实体识别提取地点、组织、人名
3. **LLM 抽取** (兜底策略): 仅在规则和 NER 无法提取时调用 LLM

**输出**: 字段列表,包含:
- `name`: 字段名称 (如"时间"、"地点")
- `value`: 字段值
- `type`: 字段类型 (time/location/number/unit)
- `confidence`: 置信度 (0-1)

#### 2.2.3 Field Normalizer (字段清洗器)

**功能**: 将原始字段名映射到 Schema 定义的标准字段名

**4 层映射策略**:

1. **精确匹配** (0 Token):
   - 字段名完全相同
   - 最快,最准确

2. **字符串相似度** (0 Token):
   - 编辑距离 (Levenshtein Distance)
   - 余弦相似度 (Cosine Similarity)
   - 阈值: 0.8

3. **同义词词典** (0 Token):
   - 预定义同义词词典
   - 覆盖 90% 常见字段
   - 支持自动扩充

4. **LLM 映射** (50% 概率):
   - 使用大语言模型
   - 语义理解和映射
   - 智能字段截断

**智能字段截断**:
- 多维度评分: 重要性 + 语义相关性 + 上下文
- 场景自适应: 根据 Schema 场景调整策略
- Token 节省: 40%+ 节省率

#### 2.2.4 Schema Manager (Schema 管理器)

**功能**: 管理 250 个预定义 Schema 模板

**Schema 分类**:
- 科研/政府 (100 个): EITV, Entity-Attribute, Cause-Effect 等
- 个人生活 (50 个): Health-Observation, Habit-Tracker 等
- 旅行/休闲 (40 个): Travel-Trip, Hotel-Stay 等
- 摄影/后期 (60 个): Shooting-Info, Exposure-Strategy 等

**Schema 结构**:
```json
{
  "schema_name": "地下水位变化事件",
  "entity_type": "EventEntity",
  "scene": "科研/政府",
  "core_fields": [
    {"name": "区域", "weight": 0.3, "required": true},
    {"name": "时间", "weight": 0.2, "required": true},
    {"name": "指标", "weight": 0.2, "required": true}
  ],
  "threshold": 0.75
}
```

**完整度评分**:
```
Completeness = Σ(字段命中次数 × 字段权重) × 来源置信度
```

当完整度 ≥ 阈值时,触发实体生成。

#### 2.2.5 Entity Builder (实体构建器)

**功能**: 从字段构建实体实例

**构建流程**:
1. **规范名称生成**: 规则生成 (50%) + LLM 生成 (50%)
2. **实体消歧**: 检测重复实体,LLM 消歧 (30%)
3. **属性增强**: LLM 提取隐含信息

**输出**: 实体对象,包含:
- `entity_id`: 唯一标识符
- `canonical_name`: 规范名称
- `type`: 实体类型
- `attributes`: 属性字典
- `supported_by`: 支撑该实体的 CKB ID 列表
- `confidence`: 置信度 (0-1)

#### 2.2.6 Relation Builder (关系构建器)

**功能**: 构建实体间的关系

**3 种关系类型**:

1. **内建关系** (0 Token):
   - 基于 Schema 定义
   - 100% 自动生成
   - 例如: has_location, has_time

2. **共现关系** (0 Token):
   - 基于实体共现
   - 统计共现频率和距离
   - 例如: co_occurs_with

3. **语义关系** (最小 Token):
   - 基于 LLM 理解
   - 分层触发: 高优先级 30% + 随机采样 20%
   - 例如: causes, influences

#### 2.2.7 Confidence Engine (置信度引擎)

**功能**: 计算和管理置信度

**实体置信度**:
```
Entity.confidence = Σ(CKB.confidence) / CKB 数量
```

**关系置信度**:
```
Relation.confidence = 
  min(source_entity_confidence, target_entity_confidence) × 0.4 +
  relation_type_confidence × 0.3 +
  evidence_strength × 0.3
```

**质量过滤**:
- 实体置信度 < 0.5 → 过滤
- 关系置信度 < 0.5 → 过滤

## 3. 核心技术

### 3.1 Token 优化策略

#### 3.1.1 规则优先

**原理**: 最大化使用规则和算法,避免 LLM 调用

**应用场景**:
- 时间提取: 正则表达式
- 数值提取: 正则表达式
- 地点提取: NER 模型
- 字段映射: 精确匹配、相似度、同义词

**Token 节省**: 70-80%

#### 3.1.2 LLM 缓存

**原理**: 缓存 LLM 响应,避免重复调用

**缓存策略**:
- 缓存键: hash(prompt)
- 缓存 TTL: 24 小时
- 缓存命中率: 70-80%

**Token 节省**: 10-15%

#### 3.1.3 智能字段截断

**原理**: 动态选择相关字段,减少 Prompt 长度

**评分维度**:
1. **字段重要性**: 权重 + 必需性 + 频率 + 通用性
2. **语义相关性**: 编辑距离 + n-gram 相似度 + 语义类别
3. **上下文相关性**: 字段类型匹配

**选择策略**:
- 至少包含前 3 个高分字段
- 最多包含 5 个字段
- 场景自适应调整

**Token 节省**: 40%+

#### 3.1.4 分层触发

**原理**: 根据优先级分层触发 LLM

**触发条件**:
- **高优先级** (30%): 因果关键词、对比关键词、多实体
- **随机采样** (20%): 发现新模式

**Token 节省**: 5-10%

**总体 Token 节省**: 90%+

### 3.2 Schema 驱动机制

#### 3.2.1 Schema 设计

**设计原则**:
1. **领域覆盖**: 覆盖科研、政府、生活等多个领域
2. **粒度适中**: 既不过于宽泛,也不过于细化
3. **可扩展**: 支持动态添加新 Schema
4. **可组合**: 支持多个 Schema 组合使用

**Schema 数量**: 250 个

**覆盖率**: 95%+ 的实际场景

#### 3.2.2 Schema 匹配

**匹配算法**:
1. 计算字段覆盖率
2. 计算语义相似度
3. 综合评分排序

**评分公式**:
```
score = field_coverage × 0.6 + semantic_similarity × 0.4
```

**阈值触发**: 完整度 ≥ 0.75 时生成实体

#### 3.2.3 Schema 学习

**自动扩充**:
- 从 LLM 映射结果中学习新同义词
- 从未映射字段中识别新模式
- 定期更新同义词词典

**质量保证**:
- 人工审核新 Schema
- 测试集验证
- 覆盖率评估

### 3.3 置信度管理

#### 3.3.1 置信度计算

**来源置信度**:
- 手动输入: 0.9-1.0
- Word/PDF: 0.8-0.9
- OCR: 0.5-0.7
- ASR: 0.4-0.6

**字段置信度**:
- 规则抽取: 0.8-0.9
- NER 抽取: 0.7-0.8
- LLM 抽取: 0.6-0.9

**实体置信度**:
- 基于支撑 CKB 的平均置信度
- 考虑 Schema 匹配度
- 考虑字段完整性

**关系置信度**:
- 基于源实体和目标实体的置信度
- 考虑关系类型
- 考虑证据强度

#### 3.3.2 级联更新

**原理**: 实体置信度变化时,自动更新相关关系的置信度

**更新规则**:
```
Relation.confidence = 
  min(source_entity.confidence, target_entity.confidence) × 0.4 +
  relation_type_confidence × 0.3 +
  evidence_strength × 0.3
```

**触发条件**:
- 实体置信度更新
- 新增支撑 CKB
- 删除支撑 CKB

#### 3.3.3 质量过滤

**过滤规则**:
- 实体置信度 < 0.5 → 标记为低质量
- 实体置信度 < 0.4 → 自动删除
- 关系置信度 < 0.5 → 标记为低质量
- 关系置信度 < 0.3 → 自动删除

**冲突消解**:
- 保留置信度最高的版本
- 合并互补信息
- 记录冲突日志
