## 改进建议

虽然系统正常工作，但对于PRD文档，当前的结果可能不是最优的：

### 1. Schema匹配问题

**当前情况**: 匹配到EITV (Entity-Indicator-Time-Value) schema
- 这是一个为科研/政府数据设计的schema
- 适合记录"某个实体在某个时间点的指标数值"
- **不太适合产品需求文档**

**建议**: 
- 为产品需求文档创建专门的schema，例如：
  - ProductRequirement schema (产品需求实体)
  - Feature schema (功能特性实体)
  - UserStory schema (用户故事实体)
  - TechnicalSpec schema (技术规格实体)

### 2. 实体名称问题

**当前实体名称**: `摄影点评专家_距离_2025-10`
- 这个名称是基于EITV schema的规则生成的
- 对于PRD文档来说语义不够清晰

**建议**:
- 为PRD类型的文档设计更合适的实体命名规则
- 例如: `影像科学产品_V1.0` 或 `PhotoScience_摄影风格分析功能`

### 3. 字段提取优化

**当前提取的字段**:
- 大量的"区域"字段（23个），但很多是误识别的
- 例如："滤镜工具区"、"观让用户看出区" 等

**建议**:
- 优化NER模型，减少对PRD文档中专业术语的误识别
- 为产品文档类型调整字段提取策略
- 增加对产品特性、功能模块、用户角色等的识别

### 4. 关系提取增强

**当前情况**: 只提取到1个关系，且信息不完整

**建议**:
- 为PRD文档设计专门的关系类型：
  - `产品-功能` 关系
  - `功能-用户角色` 关系
  - `功能-技术要求` 关系
  - `功能-依赖` 关系
