## 问题2: Schema阈值是什么？

### 定义

**Schema阈值（threshold）** 是一个0-1之间的数值，表示Schema被"触发"（匹配成功）所需的**最低加权完整度**。

### 计算公式

```javascript
// 加权完整度计算
weightedCompleteness = 映射成功字段的权重总和 / 所有核心字段权重总和

// 触发判断
if (weightedCompleteness >= threshold) {
  ✅ Schema被触发，用于构建实体
} else {
  ❌ Schema未达到阈值，不使用
}
```

### 本例中的计算

```javascript
// EITV Schema
threshold = 0.6  // 阈值60%

// 核心字段及权重
core_fields = [
  { name: "Entity", weight: 0.4 },     // 40%
  { name: "Indicator", weight: 0.15 }, // 15%
  { name: "Time", weight: 0.15 },      // 15%
  { name: "Value", weight: 0.15 },     // 15%
  { name: "Unit", weight: 0.15 }       // 15%
]

// 映射结果（全部成功）
映射字段 = 5/5
映射权重 = 0.4 + 0.15 + 0.15 + 0.15 + 0.15 = 1.0

// 计算完整度
weightedCompleteness = 1.0 / 1.0 = 100%

// 判断
100% >= 60%  ✅ 触发成功！
```

### 典型阈值设置

| Schema类型 | 阈值 | 说明 |
|-----------|------|------|
| 地下水位变化事件 | 0.75 | 高阈值，要求更多字段 |
| 政府工作报告 | 0.6 | 中等阈值，平衡准确性 |
| EITV | 0.6 | 中等阈值 |
| 区域实体 | 0.6 | 中等阈值 |
| 项目实体 | 0.7 | 较高阈值 |

### 阈值的作用

1. **控制匹配质量**: 阈值越高，要求越严格
2. **减少误匹配**: 防止不相关的Schema被触发
3. **平衡精确率和召回率**: 
   - 高阈值 → 高精确率，低召回率
   - 低阈值 → 低精确率，高召回率

## 问题3: 为什么只匹配到一个Schema？

### 直接原因

系统共处理了多个Schema，但只有**EITV Schema**达到了阈值：

```
Schema匹配结果:
✅ EITV: 完整度100%, 加权完整度100%, 阈值60% → 触发
❌ 其他Schema: 完整度<60%, 未达到阈值 → 未触发
```

### 深层原因

#### 原因1: Schema预筛选机制

系统在匹配前会根据**文档分类**筛选相关Schema：

```javascript
// 步骤1: 文档分类
文档领域 = "产品设计" (置信度85%)

// 步骤2: Schema预筛选
筛选条件: schema.scene === "产品设计" || schema.entity_type.includes("产品")

// 结果
预筛选前: 255个Schema
预筛选后: 10-20个Schema (过滤掉240+个不相关Schema)
```

**问题**: 如果Schema库主要是"地下水"、"政府报告"等领域，而缺少"产品设计"相关Schema，大部分会被过滤。

#### 原因2: 字段映射失败

其他Schema可能因为**字段映射失败**而未达到阈值：

```javascript
// 示例: 政府工作报告Schema
core_fields = [
  { name: "项目名称", weight: 0.3 },  // ❌ 文档中是"产品名称"，映射失败
  { name: "区域", weight: 0.2 },      // ❌ 文档中的"区域"是误提取，映射失败
  { name: "数值", weight: 0.15 },     // ✅ 映射成功
  { name: "单位", weight: 0.1 },      // ✅ 映射成功
  { name: "指标", weight: 0.15 },     // ✅ 映射成功
  { name: "时间", weight: 0.1 }       // ✅ 映射成功
]

// 计算
mappedWeight = 0.15 + 0.1 + 0.15 + 0.1 = 0.5 = 50%
threshold = 0.6 = 60%

// 判断
50% < 60%  ❌ 未达到阈值
```

#### 原因3: 映射表覆盖不足

**映射表** (`schema_field_mappings.json`) 可能只覆盖了部分Schema：

```javascript
// 映射表中有EITV的完整映射
"EITV": {
  "Entity": { variations: ["实体", "项目名称", "entity"] },
  "Time": { variations: ["时间", "日期", "time"] },
  "Value": { variations: ["数值", "值", "value"] },
  "Indicator": { variations: ["指标", "indicator"] },
  "Unit": { variations: ["单位", "unit"] }
}

// 但可能缺少其他Schema的映射
"政府工作报告实体": {
  // ❌ 映射表中可能没有这个Schema的条目
}
```

#### 原因4: EITV是通用Schema

EITV (Entity-Indicator-Time-Value) 设计为**通用Schema**，适用于多种场景：

```javascript
{
  schema_name: "EITV",
  description: "通用的实体-指标-时间-数值模式",
  core_fields: [
    { name: "Entity", ... },    // 任何实体
    { name: "Indicator", ... }, // 任何指标
    { name: "Time", ... },      // 任何时间
    { name: "Value", ... },     // 任何数值
    { name: "Unit", ... }       // 任何单位
  ]
}
```

这些字段名称非常通用，容易匹配到各种文档。

### 验证方法

查看系统日志可以看到详细的匹配过程：

```bash
[Pipeline] Schema预筛选完成: 10/255 个Schema (过滤掉 245 个)
[Pipeline] Schema "EITV": 完整度 100.0%, 映射字段 5/5
[Pipeline] Schema "政府工作报告": 完整度 50.0%, 映射字段 3/6
[Pipeline] Schema "项目实体": 完整度 30.0%, 映射字段 2/5
[Pipeline] Schema匹配完成: 1/10 个Schema达到阈值
```

### 解决方案

要让系统匹配更多Schema：

1. **扩展Schema库**: 添加"产品设计"、"技术文档"等领域的Schema
2. **优化映射表**: 为更多Schema添加字段映射规则
3. **调整阈值**: 降低某些Schema的阈值（如0.6→0.5）
4. **改进文档分类**: 识别更多领域，减少过度筛选
5. **禁用预筛选**: 测试时可以关闭预筛选

```javascript
// 禁用预筛选
const options = {
  schemaMatching: {
    enablePrefiltering: false
  }
};
```

### 结论

**只匹配到一个Schema是正常的**，原因是：

1. ✅ Schema预筛选过滤掉了大部分不相关Schema
2. ✅ 其他Schema的字段映射失败，未达到阈值
3. ✅ EITV是通用Schema，容易匹配成功
4. ✅ 系统按设计正确工作

**这不是bug**，而是系统的正常行为。要匹配更多Schema，需要：
- 扩展Schema库（添加更多领域的Schema）
- 完善映射表（为更多Schema添加字段映射）
