To address the issue where the "AI内涝" document is not appearing in the "Recent Activity" list in the Hi Brain module (Dashboard), I need to adjust how recent documents are fetched and filtered.

**Current Logic Analysis:**

1. **Frontend (`Dashboard.tsx`)**:

   * Uses `useDocuments` hook to fetch documents.

   * Slices the top 4 documents: `const recentDocs = documents.slice(0, 4)`.

   * It relies on the `documents` array being sorted by date.

2. **Backend (`server.js`)**:

   * `/api/documents` endpoint (line 741): `SELECT * FROM documents WHERE user_id = ? ORDER BY created_at DESC`.

   * It sorts by `created_at DESC` (creation time), **not** `updated_at` or "last viewed" time.

**The Problem:**
The user "viewed" the document, but viewing a document (via `GET /api/documents/:id`) usually doesn't update `updated_at` or `created_at` in the database. Therefore, the "Recent Activity" list currently shows the *most recently created/uploaded* documents, not the *most recently accessed* ones. If "AI内涝" was uploaded earlier than the last 4 documents, it won't show up even if viewed recently.

**Proposed Solution:**
To strictly follow the user's request ("recently viewed"), we would need a `last_viewed_at` column. However, a simpler and often sufficient fix for "Recent Activity" in this context (implied "recently interacting with") is to ensure the list reflects updates or creation.

If the user wants "Recent Activity" to show *viewed* documents, we need to:

1. **Backend**: Update `last_viewed_at` (or similar) when `GET /api/documents/:id` is called.
2. **Frontend**: Sort by `last_viewed_at` instead of `created_at`.

**However**, simpler approach first: The user might just expect it to be there if they *just* uploaded it. If they uploaded it a while ago, it's not "recent" in terms of creation.
The user said "I viewed it in the library... but didn't see it in Recent Activity". This strongly suggests they expect *access* history.

**Plan:**

1. **Database Upgrade**: Add `last_viewed_at` column to `documents` table.
2. **Backend Update**:

   * In `GET /api/documents/:id`, execute an update: `UPDATE documents SET last_viewed_at = CURRENT_TIMESTAMP WHERE id = ?`.

   * In `GET /api/documents` (list), change sort order to `ORDER BY COALESCE(last_viewed_at, updated_at, created_at) DESC`.
