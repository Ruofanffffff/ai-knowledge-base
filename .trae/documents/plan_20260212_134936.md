To fix the issue where the chat window extends indefinitely instead of scrolling within a fixed viewport, I need to adjust the layout structure in `client/src/components/Layout.tsx`.

**Root Cause:**
In `Layout.tsx`, the main content area is defined as:
```tsx
<main className="flex-1 overflow-auto">
  <div className={isMobile ? 'p-0' : 'p-6'}>
    <Outlet />
  </div>
</main>
```
The `overflow-auto` is on the `<main>` tag, but the inner `div` (with padding `p-6`) grows with its content. If the child component (like `AISearch`) tries to be `h-full`, it might extend beyond the viewport if the parent doesn't constrain it properly, or if the padding adds to the scrollable area in a way that conflicts with the child's internal scrolling.

Specifically for `AISearch` (the Dashboard), we want it to take up the full available height and handle its own scrolling internally (which we fixed in the previous step by adding `overflow-hidden` to the chat container). However, the `Layout` adds padding (`p-6`) and allows the `main` to scroll (`overflow-auto`). This double-scroll context (one on `main`, one potentially in `AISearch` if it fits) or the `main` expanding to fit `AISearch` is the problem.

**Solution:**
1.  **Modify `Layout.tsx`**:
    *   Change `<main>` to use `flex flex-col h-full overflow-hidden`. This ensures the main area takes the full height but doesn't scroll itself.
    *   Update the inner `div` to be `flex-1 flex flex-col min-h-0 overflow-hidden` (and keep the padding). This passes the height constraint down to the `Outlet`.
    *   Ensure the `Outlet` (which renders `AISearch`) can fill this container.

**Revised Layout Plan:**
```tsx
// Layout.tsx
<div className="flex h-screen bg-slate-50 overflow-hidden"> {/* Ensure body doesn't scroll */}
  <Sidebar ... />
  <main className="flex-1 flex flex-col h-full overflow-hidden relative">
    <div className={`flex-1 flex flex-col min-h-0 ${isMobile ? 'p-0' : 'p-6'}`}>
       <Outlet />
    </div>
  </main>
</div>
```

**Wait, `AISearch` itself needs to be `h-full` to work.**
In `AISearch.tsx`, the root element is:
```tsx
<div className="flex-1 h-full flex ...">
```
If the parent in `Layout.tsx` allows scrolling (`overflow-auto`), then `h-full` on `AISearch` might result in it being at least the height of the viewport, but if content grows, the `Layout` scrolls. We want `Layout` *not* to scroll, and `AISearch` to be exactly the height of the container so *its* internal message list scrolls.

**Plan:**
1.  Update `client/src/components/Layout.tsx`:
    *   Remove `overflow-auto` from `<main>`.
    *   Add `h-full` and `overflow-hidden` to `<main>`.
    *   Ensure the inner `div` wrapping `<Outlet />` is also `h-full` (or `flex-1`) so the `Outlet` content receives the fixed height constraint.

This will force `AISearch` to be fixed to the viewport height (minus padding), allowing its internal `overflow-hidden` and `overflow-y-auto` logic to work correctly for the message list.
