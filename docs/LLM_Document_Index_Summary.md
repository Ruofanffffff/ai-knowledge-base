## 文档 26：广东省税务局信息化总体规划

**广东省税务局2019–2022信息化总体规划的核心主旨是：以"大智能、大平台、大集成、大生态、大安全"为理念，构建以纳税人体验为导向、以风险与信用为手段、以技术与数据为支撑、以开放互联网生态为依托的"四位一体"智慧税务现代治理体系。**

**核心概念及其角色：**
- **智慧税务（愿景）**：顶层设计目标与价值锚点，统领全部建设逻辑；
- **三大税务应用（征管/数据/行管应用）**：业务落地主体，分别承载办税服务、数据治理与行政管理职能；
- **六大支撑平台（渠道/统一工作/通用业务/数据服务/数据管控/运维管理）**：能力中台，提供标准化、组件化、可复用的技术与业务支撑；
- **统一基础设施（"一片云+一张网+双活容灾"）**：物理与逻辑底座，保障弹性、安全、高可用的运行环境；
- **八大创新特色（如掌上税务、自主运维、联创中心等）**：差异化实施路径与突破抓手，体现前瞻性与广东实践特色；
- **组织/人才/制度保障体系**：治理主体，确保规划可持续执行与能力内生；
- **"三化"建设（标准化、规范化、一体化）**：方法论主线，贯穿规划、建设、运维全周期。

**关键关系：**
- **目标—架构—实施的递进统合关系**：智慧税务愿景驱动整体架构设计（"三大应用—六大平台—统一基础设施"分层解耦），架构又反向约束并指导八大创新与专项项目落地；
- **支撑—赋能—协同的双向强化关系**：六大平台作为能力中枢，向上赋能三大应用（如通用业务平台解耦电子税务局与金税三期）、向下整合基础设施（如运维平台纳管云资源），同时横向打通税务系统内外生态（如渠道平台对接"粤省事"、数据平台联通"数字政府"）；
- **问题—改革—能力的闭环演进关系**：现状分析中识别的"系统孤岛、数据割裂、运维薄弱、组织缺位"等结构性问题，直接催生"三化"建设原则与联创中心、自主运维、数据管控等创新举措，最终沉淀为组织、人才、制度等长效治理能力；
- **技术—业务—治理的深度融合关系**：大数据、AI、区块链等技术非孤立应用，而是深度嵌入信用风险管税（技术驱动风控）、掌上税务（技术重塑体验）、决策指挥中心（技术赋能治理）等业务场景，并通过安全可控、开放共享等原则实现技术主权与生态协同的再平衡。

## 文档 27：贵阳机场T3闸机项目

**主旨：**
贵阳T3航站楼预安检闸机系统通过西南凯亚建设的闸机管理系统，实现与闸机硬件及厦门凯亚安检信息系统（SMIS）的多向数据对接，支撑实名核验、值机状态判断、托运行李开包拦截等核心预安检功能，构建安全、可控、高可用的自动化旅客通行验证闭环。

**核心概念及其角色：**
- **闸机（硬件主体）**：12台物理通行终端（国内8台/国际4台），承担身份证读取、人像采集、人证比对、公安库比对、本地控制执行（开门/拒行/显示/语音）；是业务入口与执行端。
- **闸机管理系统（系统枢纽）**：由西南凯亚承建，作为中间服务层，提供通行验证接口、解析存储旅客数据、调用SMIS接口、转发结果至闸机、推送过检信息至SMIS；是逻辑调度与数据中转核心。
- **安检信息系统（SMIS，外部依赖系统）**：由厦门凯亚提供，暴露值机状态与托运行李开包状态两个关键查询接口，并接收闸机管理系统推送的预安检旅客全量信息；是权威业务数据源与下游安检协同基础。
- **公安重点人员数据库（外部安全源）**：用于实时身份风险筛查，嵌入闸机本地比对环节，属前置安全校验依赖项。
- **二代身份证（唯一认证凭证）**：系统唯一支持的实名核验介质，定义适用边界与人工通道触发条件。
- **人工通道（兜底机制）**：处理非二代证、员工通行、多值机记录等系统约束场景，体现人机协同设计原则。

**关键关系：**
- **流程依赖**：闸机 →（发起请求）→ 闸机管理系统 →（转发并调用）→ SMIS / 公安库；SMIS返回结果 →（经闸机管理系统处理）→ 反馈至闸机执行控制；旅客通行后 →（闸机管理系统主动推送）→ SMIS完成数据闭环。
- **功能包含**：闸机管理系统封装了"请求解析—跨系统调用—结果聚合—指令下发—事件推送"全链路能力，是系统集成中枢。
- **安全约束**：所有接口访问需授权验证，数据传输强制加密压缩；系统设计以机场安全为最高前提，功能实施与运维均服从该目标。
- **边界限定**：仅支持航信系航空公司及二代身份证，形成明确的技术与业务适用范围；人工通道与员工通道作为刚性补充，与自动化流程构成互补而非替代关系。

## 文档 29：以萨神眼车辆大数据系统技术方案

**主旨：**
"以萨神眼车辆大数据系统"是以人工智能与计算机视觉为核心，面向公安实战需求构建的、支持跨区域联网、全链条智能分析与多警种协同应用的车辆图像结构化处理与大数据研判平台。

**核心概念及其角色：**
- **以萨神眼车辆大数据系统**：主体，整体技术方案的承载体与实施对象；
- **车辆图像二次识别**：核心方法，实现非结构化图片向高精度结构化特征（品牌/型号/年款/局部特征/驾乘行为等）的智能转化；
- **公安实战应用**：根本目标，覆盖"事前防控—事中指挥—事后研判"全业务流程，支撑侦查破案、布控预警、交通治理等具体警种任务；
- **视频大数据融合分析**：关键工具，依托分布式架构（Kafka+Redis+GPU/CPU异构计算+亿级图像集群）、多源接入（卡口/电警/视频/车管库/人员库）与深度关联碰撞能力；
- **双网/单网部署架构**：基础支撑，解决视频专网解析与公安网应用间的跨网安全传输与性能平衡问题；
- **神眼APP与实战子系统**：应用延伸，提供移动化查车、周边预警、布控响应及"一车一档"等轻量化、场景化服务接口。

**关键关系：**
- **因果关系**：前端设备存量丰富但数据孤岛→催生"二次识别+联网计算"技术路径；犯罪手段升级（套牌、昼伏夜出、双胞胎车等）→驱动"多维特征建模+时空轨迹研判"等高级算法研发；
- **依赖关系**：实战功能（如以图搜车、同行车辆分析）高度依赖二次识别输出的细粒度结构化数据；系统高并发实时性依赖GPU异构计算与Kafka消息队列等底层技术支撑；
- **包含关系**："系统总体框架"包含采集层、网络层、数据层、服务层、应用层、表现层、用户层七层逻辑架构；"系统关键技术"包含计算机视觉、深度学习（CNN/SVM/FP-growth）、GPU加速、分布式计算（DTC/Kafka）等子技术栈；
- **对比关系**：双网架构（视频网解析+公安网应用）与单网架构在部署成本、安全性、带宽占用上形成权衡选择；基础版与扩展版功能（如搜车、研判、布控）体现能力梯度演进与项目适配弹性。
